# 11 · 视觉令牌与主题

## 定位

`frontend/src/themes.css` 是全项目**唯一**的色值与尺寸刻度定义处。
`ep-theme.css` 把 Element Plus 的变量接到 `--nt-*`。
完整的设计语言（布局、五态、文案）见 [DESIGN.md](../DESIGN.md)，这里只讲令牌本身。

## 设计

### 中性九档

全站唯一的灰阶，纯灰（R=G=B），不夹蓝紫偏色。

| 档 | 值 | 用途 |
|---|---|---|
| `--nt-gray-1` | `#212529` | 正文（浅色主题）、深色主题的内容底 |
| `--nt-gray-2` | `#343a40` | 次要文字（浅色） |
| `--nt-gray-3` | `#495057` | 三级文字（浅色） |
| `--nt-gray-4` | `#6c757d` | 占位符 / 禁用态（浅色）、四级文字（深色） |
| `--nt-gray-5` | `#adb5bd` | 装饰（浅色）、三级文字（深色） |
| `--nt-gray-6` | `#ced4da` | 描边（浅色）、二级文字（深色） |
| `--nt-gray-7` | `#dee2e6` | 描边 / 分隔（浅色） |
| `--nt-gray-8` | `#e9ecef` | 悬停底（浅色） |
| `--nt-gray-9` | `#f8f9fa` | 窗底 / 壳底（浅色）、正文（深色） |

**奇数档是锚点，偶数档是补齐的中间档**。没有中间档时悬停与选中只能靠
透明度硬造，叠在深色上就糊成一片。

### 墨色四级阶梯

墨色是「字有多重」，与灰阶的「面有多亮」是两件事，所以单独一级。

| 令牌 | 浅色 | 深色 | 白底对比度 | 承载什么 |
|---|---|---|---|---|
| `--nt-ink` | 灰1 | 灰9 | 15.4:1 | 正文 |
| `--nt-ink-2` | 灰2 | 灰6 | 11.5:1 | 次要文字 |
| `--nt-ink-3` | 灰3 | 灰5 | 8.2:1 | 三级文字 |
| `--nt-ink-muted` | 灰4 | 灰4 | 4.7:1 | 占位符 / 禁用态 |

**`muted` 卡在 AA 边缘是刻意的**：它承载占位符与禁用态，低于 4.5:1
就真的读不清了；再往上提又会让禁用态看起来像正常文字。

### 表面六级阶梯

```
window（窗底） < workspace（区底） ≤ surface（面板 / chrome）
≤ raised（卡片 / 弹窗） < hover（悬停底） < selected（选中底）
```

| 阶梯 | 浅色 | 深色 |
|---|---|---|
| `--nt-elev-window` | 灰9 | `#191c1f` |
| `--nt-elev-workspace` | `#ffffff` | 灰1 |
| `--nt-elev-surface` | 灰9 | `#191c1f` |
| `--nt-elev-raised` | `#ffffff` | `#262a2e` |
| `--nt-elev-hover` | 灰8 | 灰2 |
| `--nt-elev-selected` | 灰7 | 灰3 |

相邻两级只差 2%~5% 亮度——读起来是一片连续的工作区，而不是卡片叠卡片。

语义名（`--nt-bg` / `--nt-surface` / `--nt-surface-2` / `--nt-surface-hover` /
`--nt-surface-selected`）是指向阶梯的别名。**新代码一律写 `--nt-elev-*`**，
别名不许单独赋色值（否则会盖掉阶梯）。

### chrome 与内容的两级亮度

`--nt-chrome` 单独一档：标题栏、菜单栏、工具栏、标签栏、状态栏、侧栏
统一落它，编辑区落 `--nt-editor-bg`。**整窗只有「壳」与「内容」两级亮度**，
靠 1px 描边分界，而不是靠卡片叠卡片。

### 控件令牌

表单控件另走一组 `--nt-control-*`：控件要有「可以点进去」的浮凸感，
与普通面的描边平铺区分开。

```
--nt-control-bg / bg-hover / bg-disabled
--nt-control-border / border-hover
--nt-control-shadow / shadow-focus
```

### 编辑器表面

`--nt-editor-*` 一组（bg / gutter-bg / gutter-ink / active-line / selection /
cursor）：代码区可独立压暗，不让界面 chrome 的亮色抢走代码的注意力。

### 尺寸刻度

| 组 | 变量 |
|---|---|
| 字号 | `--nt-fs-2xs`(10) ~ `--nt-fs-3xl`(32)，8 级 |
| 间距 | `--nt-sp-1`(4) ~ `--nt-sp-6`(24) 加 `sp-8`(32) / `sp-10`(40) / `sp-12`(48)，共 9 档 |
| 圆角 | `--nt-radius-xs`(4) / `sm`(6) / `radius`(8) / `lg`(12) / `xl`(14) / `full`（六档） |
| 控件高度 | `--nt-ctl-h-sm`(26) / `ctl-h`(34) / `ctl-h-lg`(38) / `ctl-h-xl`(44) / `ctl-icon`(32) |
| Chrome 高度 | `--nt-h-menu`(32) / `toolbar`(34) / `tab`(32) / `sidebar-header`(30) / `status`(26) |
| 图标尺寸 | `--nt-icon-sm`(14) / `icon-md`(16) / `icon-lg`(18) |
| 图标瓦片 | `--nt-tile-sm`(30) / `tile`(40) / `tile-lg`(52) |
| 布局宽度 | `--nt-w-sidebar`(260) / `dialog`(560) 等 |

**两套缩放系数管两件事**：

| 系数 | 来源 | 管什么 |
|---|---|---|
| `--nt-vw-scale` | 窗口宽 ÷ 1440，上下限 0.8~1.35 | 间距、控件高度、图标尺寸、圆角 |
| `--nt-fs-scale` | 外观设置 80%~140% | **只有字号** |

字号不乘视口系数：窗口变窄不该把字变小，那把「小屏看清」变成「小屏看不见」。
文字大小只由用户自己控制。

### 主题三档

`theme: light | dark | system`。`system` 时 `resolvedTheme` 跟随
`prefers-color-scheme`，并在系统切换时实时更新（不用重启）。

`[data-theme]` 写在 `<html>` 上，由 `stores/settings` 的 `applyTheme()` 维护。
切换时挂一次性 `.nt-theme-switching` 类跑 200ms 过渡，结束即摘——
常驻过渡会让窗口缩放、侧栏拖拽都跟着变质。

## 约束

- **色值只在 `themes.css` 定义**：组件只允许 `var(--nt-*)`，不用 hex；
- **引用不存在的变量会静默失效**——那不是「样式不好看」，是**静默丢样式**，
  最危险。新增令牌时 grep 一遍引用处；
- **图标尺寸写在自己的根元素上**：`NtIcon` 的根元素就是 `<svg>`，
  写成 `.nt-icon svg` 是后代选择器、永远选不到自己，SVG 会退化成 auto
  并被父容器撑满；
- 渐变只允许三处：图表面积（`--nt-ch-*`）、欢迎页光晕、用户自选的背景图；
- 分层靠「圆角 + 1px 中性描边 + 一层极轻阴影」（`--nt-card-shadow`）：
  禁彩色描边、禁 backdrop-blur 叠层；
- 胶囊只给真正的圆形（状态点 / 滚动条）；chip 与输入框走 `radius-sm`
  （小控件上套满圆角就是一根胶囊，反而看不出「可以点进去」的边界）；
- 强调色只有同一个靛蓝色相的五档，没有第二个色相；
- 数据可视化取 `--nt-ch-1..4`（靛蓝明度递减）。

## 取舍

**手写 EP 主题桥而不是引 `element-plus/theme-chalk` 的暗色变量**：
theme-chalk 的暗色是一整套独立的色值，与我们的六级阶梯对不上。
接过来要让「EP 的灰」和「我们的灰」在两套主题里各自对齐，
而写桥只需要 40 行。代价是 EP 升级时要核对一遍变量名有没有变。

**不引 Tailwind**：UnoCSS 的 presetUno 已覆盖所需原子类，
且刻度能接到 `--nt-*`。Tailwind 的默认色板会诱使组件写 `bg-gray-100`，
而那正是令牌纪律要防的。

**只做两套主题，不做多套配色**：多套主题的维护成本不在「加一套」，
而在「每套都要过一遍对比度与图表色」。两套做扎实，收益高于十套半成品。
