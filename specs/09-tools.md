# 09 · 工具箱

## 定位

`src-tauri/src/service/tools.rs`：JSON / Diff / 哈希 / 正则 / 行编辑 / 编码转换。
全是纯计算，不落库、不碰窗口。前端每个工具箱是一个浮窗，
调这里拿到结果后渲染。

## 设计

### JSON

| 能力 | 实现 |
|---|---|
| 格式化 / 压缩 | 自写 `pretty_json(v, indent)`：serde_json 的 `to_string_pretty` 固定两空格，而设置里允许 0–8 |
| 键排序 | `sort_json` 递归排序对象键（对比两份配置时先排序，diff 才看得出差异） |
| 校验 | `serde_json::from_str` 的 `Error` 带 `line()` / `column()`——只说「格式错误」用户找不到在哪 |
| JSONPath | 极简实现：`$` / `$.a.b` / `$[0]` / `$..key` / `$.a[*]` |
| 转结构体 | 5 种语言（Rust / Go / TS / Java / Python），按各自命名风格（snake / pascal / camel） |

**JSONPath 是简化版**：不支持 `$..` 后再接路径（`$..a.b` 报错）。
完整实现要一个独立的 parser，而工具窗里 95% 的查询是 `$.a.b` 与 `$..name`。

### Diff

```
text_diff(req) -> TextDiffVO
  ├─ 归一（可忽略空白 / 大小写 / 空行）
  ├─ LCS 动态规划求行级对齐
  ├─ 每行给 op（equal / added / removed）+ 行号
  └─ 行内 span：相邻的删除 / 插入行按序配对，前后缀相同的部分不标，只标中间变化段
```

**LCS 上限 400 万格**（`n * m`）：超了退化成「全删再全插」的简化输出。
O(n·m) 的内存会到 16MB+，而 diff 视图本来就看不下来几千行。
`changed` 字段给「有内容变化的行数」（added + removed）。

**`left_spans` / `right_spans` 是 `[start, end)` 区间，偏移按 UTF-16 码元**
（前端 `String.slice` 的下标口径，中文等多字节字符不会错位）：
前端按它包 `<span class="nt-span">`，文本先转义再插 span
（`DiffToolDialog.vue` 的 `spansHtml`），避免注入。

### 目录对比

一层目录，逐文件比较：

| status | 判据 |
|---|---|
| `same` | 大小相同**且**逐字节相同 |
| `diff` | 大小不同，或字节不同 |
| `left_only` / `right_only` | 只在一侧存在 |

大小相同也要逐字节比：mtime 改了但内容没改是常见情况。

### 哈希

MD5 / SHA-1 / SHA-256 三种，**全部手写实现**（标准库不暴露原始接口）。

选这三种的理由：命令行工具（`certutil` / `Get-FileHash`）默认就出它们，
用户要对照校验时不用先猜算法。哈希是单函数行为，不设链路测试（见 [12](12-testing.md)）。

### 正则（迷你引擎）

支持：

| 语法 | |
|---|
| 字面量、`.`、`*`、`+`、`?` | |
| `[...]` 字符组（含 `^` 否定与 `a-z` 区间） | |
| `\d \w \s \D \W \S` | |
| `^`、`$` | `$` 在行尾也成立（等价 `/m`，测试器默认就要这样） |
| `(...)` 捕获组（非嵌套） | |
| `\|` 顶层交替 | |

不支持：反向引用、命名组、lookaround、`{n,m}` 量词。

**贪心 + 回溯**：`*` / `+` 先吃最长，失败再吐。深度由输入长度封顶，
不会栈溢出（最长输入受 32MB 读取上限约束）。

**空匹配必须推进一位**：否则 `a*` 在空串上死循环，挂住 UI。

**匹配上限 1000 条**：超出截断并置 `truncated`，
前端显示「仅前 1000 条」——一次渲染上万条会把界面卡死。

**要支持 `{n,m}` 与命名组时换 `regex` crate**（[AGENTS.md §1.1](../AGENTS.md)）。
手写引擎让二进制省 ~1MB，代价是语法面窄。

### 编码与行尾转换

`convert_line_ending` 在文本层做（先归一成 LF，再按目标展开）。
`convert_case` 复用 `editor::apply_line_op` 的 `ToTitle` / `InvertCase`。

**编码转换只改「怎么写」**：用户看到的一直是解码后的 Unicode，
落盘时才按目标编码编码（`service::file::write` 的逻辑）。
`ConvertReq.from` 字段保留给「从原始字节重解」的场景，目前未用。

## 约束

- 工具箱不落库：`ToolsService` 持有一个内存数据库句柄只为构造签名一致
  （容器统一 `new`），将来加「历史记录」时不用改容器；
- 出参的 `error_message` 是 `Option<String>`，`ok: false` 时必给；
- 正则的 `named` 组字段预留（当前引擎不支持），前端按固定列表渲染编号组。

## 取舍

**哈希与正则手写而不引 crate**：`sha2` + `regex` 会让二进制 +2MB，
而编辑器的使用场景（算个校验和、试个模式）不需要完整实现。
代价是要自己维护正确性——所以三种哈希各有一个已知向量测试，
正则的边界（空匹配推进、捕获组编号）也有测试。

**JSONPath 简化版**：完整实现是一个独立 parser，
而工具窗里的查询 95% 是 `$.a.b` 与 `$..name`。
不支持的语法直接报错（「暂不支持 $.. 后再接路径」），不静默给错结果。

## Markdown 三态与格式转换（纯前端）

这两件事不走 invoke：文档都是小体积（配置几 KB、Markdown 几十 KB），
走一趟 IPC 反而慢；而且转换失败时要立刻在输入框旁边定位，前端算完直接显示。

**Markdown 三态**（`composables/useMarkdown.ts` + `editor/MarkdownEditor.vue`）：
编辑 / 分屏 / 预览。`.md` 默认进三态视图而不是只读预览——用户点开一个 `.md`
是想改它，不是想先看一遍再找按钮切回编辑。编辑态就是普通 CodeEditor，
复用它的撤销历史、快捷键、右键菜单。

渲染分三步异步：HTML（markdown-it + DOMPurify）→ 图（Mermaid）→ 公式（KaTeX）。
每步用一个递增 token 守卫：**旧文本的图不能覆盖新文本的图**。
代码块里的 `$` 不当公式（跳过 `pre` / `code` 的文本节点）；
Mermaid 渲染失败退回源码——比留一块空白好，用户能看出是哪句写错了。

**排版口径**（`content.css` 的 `.nt-md-doc`）：一条 52em 的左对齐阅读栏。
所有块级元素只吃 `max-width`，不吃固定宽度；长 URL / 长路径靠
`overflow-wrap: anywhere` 断行，代码块与宽表格在**自身内部**横向滚动。
分屏窄到 380px 时，预览面板也不该出现整页横向滚动条。

**标题锚点**：markdown-it 默认不生成 `id`，文档自带的目录点了没反应。
渲染器按 GitHub 的 slug 规则给每个标题补 `id`（小写、去标点、空格转连字符、
保留中日韩字符），重复标题依次加 `-1` `-2`。预览里的 `#anchor` 在面板内平滑跳转
并闪一次落点底色；`http(s)` 交给系统浏览器；其余按相对路径打开同目录文件。

**相对图片**：`![](./img/a.png)` 按当前文件所在目录解析成绝对路径，
再走 `convertFileSrc`（asset 协议）。按页面 URL 解析必然 404。

**分屏比例可拖**：中缝 6px 热区（视觉 1px），比例限制在 25%~75%。

**打开就是编辑态**：`.md` 与其他文本文件一样从左上角的源码开始，要看渲染结果
按「分屏 / 预览」。不做「记住上次模式」——切过一次就永远不再给源码，
下次打开的人会以为文件坏了。

**面板根类名不能叫 `.nt-md`**：`content.css` 里 `.nt-md` 是帮助页渲染结果的
容器（`max-width: 860px` + `margin: 0 auto`）。挂到编辑器面板上，
整块面板会被压窄并居中——编辑器、行号、预览一起漂到屏幕中间。

**格式转换**（`dialogs/ConvertDialog.vue`）：JSON / YAML / TOML / XML 互转。
XML 的属性以 `@_` 前缀挂在节点上，数字 / 布尔自动转型
（`<port>8080</port>` 该是数字不是字符串）。解析库全部动态 import：
只转 JSON 的人不该付 YAML/TOML/XML 的加载代价。

**导出 HTML 内联样式**：导出的文件要在别的机器 / 浏览器里打开，
那里没有 `themes.css`，所以固定浅色底 + 等宽正文保证可读。

## 目录对比 / 取色器 / 日志查看器

- **目录对比**：后端 `dir_diff` 扫一层目录、逐文件比较（进子目录的诉求交给
  左右各开一个文件夹再比），前端只负责选目录、展示、跳转。
  四态（仅左 / 仅右 / 不同 / 相同）用**语义色文字**而不是底色——
  一屏几十行铺底色会花；差异排在前面，相同的排到最后；
- **取色器**：EyeDropper API（WebView2 的 Chromium 内核支持），
  不支持时退化为手动输入色值的 HEX/RGB/HSL 互换。不做截图取色——
  那要额外拿屏幕捕获权限，代价远大于收益；
- **日志查看器**：直接读后端 `app.log`，按**级别字段**着色而不是按关键词
  （关键词会把正文里的 error 也涂红）。只取最后 2000 行：日志可能几十 MB，
  全渲染会把界面卡死。解析不出来的行按 info 收进去——丢掉一整行
  比把它标错级别更糟，用户要找的就是那一行。
