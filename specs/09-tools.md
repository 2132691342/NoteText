# 09 · 工具箱

## 定位

`src-tauri/src/service/tools.rs`：JSON / Diff / 哈希 / 正则 / 行编辑 / 编码转换。
全是纯计算，不落库、不碰窗口。前端每个工具箱是一个浮窗，
调这里拿到结果后渲染。

## 设计

### JSON

| 能力 | 实现 |
|---|---|
| 格式化 / 压缩 | 自写 `pretty_json(v, indent)`：serde_json 的 `to_string_pretty` 固定两空格，而设置里允许 0–8 |
| 键排序 | `sort_json` 递归排序对象键（对比两份配置时先排序，diff 才看得出差异） |
| 校验 | `serde_json::from_str` 的 `Error` 带 `line()` / `column()`——只说「格式错误」用户找不到在哪 |
| JSONPath | 极简实现：`$` / `$.a.b` / `$[0]` / `$..key` / `$.a[*]` |
| 转结构体 | 5 种语言（Rust / Go / TS / Java / Python），按各自命名风格（snake / pascal / camel） |

**JSONPath 是简化版**：不支持 `$..` 后再接路径（`$..a.b` 报错）。
完整实现要一个独立的 parser，而工具窗里 95% 的查询是 `$.a.b` 与 `$..name`。

### Diff

```
text_diff(req) -> TextDiffVO
  ├─ 归一（可忽略空白 / 大小写 / 空行）
  ├─ LCS 动态规划求行级对齐
  ├─ 每行给 op（equal / added / removed）+ 行号
  └─ 行内 span：找最近的插入/删除行做字符级对比
```

**LCS 上限 400 万格**（`n * m`）：超了退化成「全删再全插」的简化输出。
O(n·m) 的内存会到 16MB+，而 diff 视图本来就看不下来几千行。
`changed` 字段给「忽略空白后仍存在差异的行数」，目录对比用它标记「有实质差异」。

**`left_spans` / `right_spans` 是字节区间**：前端按它包 `<span class="nt-span">`，
文本先转义再插 span（`DiffToolDialog.vue` 的 `spansHtml`），避免注入。

### 目录对比

一层目录，逐文件比较：

| status | 判据 |
|---|---|
| `same` | 大小相同**且**逐字节相同 |
| `diff` | 大小不同，或字节不同 |
| `left_only` / `right_only` | 只在一侧存在 |

大小相同也要逐字节比：mtime 改了但内容没改是常见情况。

### 哈希

MD5 / SHA-1 / SHA-256 三种，**全部手写实现**（标准库不暴露原始接口）。

选这三种的理由：命令行工具（`certutil` / `Get-FileHash`）默认就出它们，
用户要对照校验时不用先猜算法。三种各有一个已知向量测试
（`test_tools_chain`），与命令行输出对不上时测试先红。

### 正则（迷你引擎）

支持：

| 语法 | |
|---|
| 字面量、`.`、`*`、`+`、`?` | |
| `[...]` 字符组（含 `^` 否定与 `a-z` 区间） | |
| `\d \w \s \D \W \S` | |
| `^`、`$` | `$` 在行尾也成立（等价 `/m`，测试器默认就要这样） |
| `(...)` 捕获组（非嵌套） | |
| `\|` 顶层交替 | |

不支持：反向引用、命名组、lookaround、`{n,m}` 量词。

**贪心 + 回溯**：`*` / `+` 先吃最长，失败再吐。深度由输入长度封顶，
不会栈溢出（最长输入受 32MB 读取上限约束）。

**空匹配必须推进一位**：否则 `a*` 在空串上死循环，挂住 UI。
`test_tools_chain` 有一条专门守护这个。

**匹配上限 1000 条**：超出截断并置 `truncated`，
前端显示「仅前 1000 条」——一次渲染上万条会把界面卡死。

**要支持 `{n,m}` 与命名组时换 `regex` crate**（[AGENTS.md §1.1](../AGENTS.md)）。
手写引擎让二进制省 ~1MB，代价是语法面窄。

### 编码与行尾转换

`convert_line_ending` 在文本层做（先归一成 LF，再按目标展开）。
`convert_case` 复用 `editor::apply_line_op` 的 `ToTitle` / `InvertCase`。

**编码转换只改「怎么写」**：用户看到的一直是解码后的 Unicode，
落盘时才按目标编码编码（`service::file::write` 的逻辑）。
`ConvertReq.from` 字段保留给「从原始字节重解」的场景，目前未用。

## 约束

- 工具箱不落库：`ToolsService` 持有一个内存数据库句柄只为构造签名一致
  （容器统一 `new`），将来加「历史记录」时不用改容器；
- 出参的 `error_message` 是 `Option<String>`，`ok: false` 时必给；
- 正则的 `named` 组字段预留（当前引擎不支持），前端按固定列表渲染编号组。

## 取舍

**哈希与正则手写而不引 crate**：`sha2` + `regex` 会让二进制 +2MB，
而编辑器的使用场景（算个校验和、试个模式）不需要完整实现。
代价是要自己维护正确性——所以三种哈希各有一个已知向量测试，
正则的边界（空匹配推进、捕获组编号）也有测试。

**JSONPath 简化版**：完整实现是一个独立 parser，
而工具窗里的查询 95% 是 `$.a.b` 与 `$..name`。
不支持的语法直接报错（「暂不支持 $.. 后再接路径」），不静默给错结果。
