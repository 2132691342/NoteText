# 错误码

## 定位

码段划分、message 写法与前端按码补的动作。新增一个码要三处一起改：
`pkg/error.rs`、`locales/{zh-CN,en}.ts` 的 `errCode` 段。

后端 `AppError` 的码值是**数字字符串**（`"1001"`），不是 int：
前端要靠 code 分流，而 int 会被误读成状态码。字符串从类型上把两者分开。

每个码的 message 已经是人话（带下一步），前端 `utils/errors.ts` 的
`nextStep()` 按码段补第二步动作，两端不重复同一句话。

## 1000–1999 通用 / 文件 / 路径

| 码 | 常量 | 含义 | 前端动作 |
|---|---|---|---|
| 1000 | `PATH_EMPTY` | 路径为空 | 提示用户选一个位置 |
| 1001 | — | 文件读写失败（`From<io::Error>`） | 翻译 os error：32 = 被占用、5 = 无权限、3 = 路径不存在 |
| 1002 | — | 数据格式解析失败（`From<serde_json::Error>`） | 通常是备份文件损坏，提示重新导出 |
| 1003 | `PATH_ESCAPE` | 路径越界，或目标已存在 / 目录将移进自己的子目录 | 提示换位置保存、换目标名，或检查路径里的 `..` |
| 1004 | `FILE_TOO_LARGE` | 文件超过全量读取上限（32MB） | 提示用「只读前段」模式打开 |
| 1005 | `FILE_NOT_FOUND` | 文件或目录不存在 | 从最近文件列表里清掉该项 |
| 1006 | `CLIPBOARD_FAILED` | 剪贴板打不开 / 被其他程序占用 | 稍后重试；粘贴可改用 Ctrl+V 原生链路 |

## 2000–2999 配置 / 持久化 / DB

| 码 | 常量 | 含义 | 前端动作 |
|---|---|---|---|
| 2001 | `DB_FAILED` | 数据库操作失败 | 提示重启；持续出现则引导看日志 |
| 2002 | `MIGRATION_FAILED` | 建表 / 迁移失败 | 同上；这一般是磁盘满或权限问题 |

## 3000–3999 编码

| 码 | 常量 | 含义 | 前端动作 |
|---|---|---|---|
| 3001 | `ENCODE_FAILED` | 按探测到的编码解码失败 | 提示在状态栏手动选编码重新载入 |

**探测不到时不报错**：`detect()` 给 `windows-1252` 兜底并置 `low_confidence`，
状态栏的编码名后带 `?`。让用户手选比报错好——报错等于「打不开」，
而大多数情况用户知道这是什么编码。

## 4000–4999 编辑器域

| 码 | 常量 | 含义 | 前端动作 |
|---|---|---|---|
| 4001 | `TAB_NOT_FOUND` | 标签不存在 / 该语言不支持行注释 / 行号从 1 开始 | 刷新标签后重试 |

## 5000–5999 工具箱

| 码 | 常量 | 含义 | 前端动作 |
|---|---|---|---|
| 5001 | `JSON_INVALID` | 不是合法 JSON | `JsonFormatVO` 已带行列号，前端直接定位 |
| 5002 | `REGEX_INVALID` | 正则表达式有误 | 提示去掉正则选项再试，或检查语法 |
| 5003 | `HASH_FAILED` | 哈希计算失败 | 一般是文件读不了，回看 1001 |

## 6000–6999 监控

| 码 | 常量 | 含义 | 前端动作 |
|---|---|---|---|
| 6001 | `WATCH_FAILED` | 文件监控启动失败 | 提示重启；仍失败则换一个目录作为工作目录 |

**监控失败不阻断启动**：编辑器核心功能不依赖它，失败只让侧栏的监控面板不可用。

## 7000–7999 壳层

| 码 | 常量 | 含义 | 前端动作 |
|---|---|---|---|
| 7001 | `SHELL_FAILED` | 系统能力调用失败（对话框 / 托盘 / 打开路径） | 提示重启 |
| 7002 | `FILE_ASSOC_FAILED` | 文件关联读写注册表失败 / 未知分组 / 非 Windows | 以当前用户重试，或到系统设置里检查默认应用 |

## 8000–8999 用户数据

| 码 | 常量 | 含义 | 前端动作 |
|---|---|---|---|
| 8001 | `BOOKMARK_FAILED` | 书签操作失败 | 刷新面板；持续出现看日志 |
| 8002 | `SNIPPET_FAILED` | 片段操作失败（含名字为空） | 提示片段名字不能为空 |
| 8003 | `MACRO_FAILED` | 宏操作失败（含空步骤） | 提示宏至少要有一个步骤 |
| 8004 | `DRAFT_FAILED` | 草稿操作失败 | 同上 |

## 9000–9999 压缩 / 归档

| 码 | 常量 | 含义 | 前端动作 |
|---|---|---|---|
| 9001 | `ARCHIVE_UNSUPPORTED` | 格式不在支持清单里 | 提示换 7z / zip / tar 系或单文件压缩格式 |
| 9002 | `ARCHIVE_PASSWORD_REQUIRED` | 归档有加密内容但没给密码 | 浏览浮窗内出现密码行，输入后原窗重试 |
| 9003 | `ARCHIVE_WRONG_PASSWORD` | 密码不对 | 同上；提示检查大小写 |
| 9004 | `ARCHIVE_CORRUPT` | 归档损坏或流解不开 | 提示确认传输完整 |
| 9005 | `ARCHIVE_BAD_REQUEST` | 参数有误（单文件格式多源、方法不支持等） | 提示改参数重试 |
| 9006 | `ARCHIVE_CANCELLED` | 任务被用户取消 | 静默：任务面板标「已取消」，不弹错误 |

**密码三态分流**在 `service/archive/util.rs`：库的 `PasswordRequired` /
`InvalidPassword` 与「给过密码没有」组合出 9002 / 9003 两种码——
前端靠码判断要不要显示密码框，靠「是否已给密码」判断提示语。

**9006 不算失败**：队列收尾时按 `code == 9006` 把状态落成 `cancelled` 而不是
`failed`，toast 说「已取消」而不是「失败」。

## 前端自有码

| 码 | 含义 | 处理 |
|---|---|---|
| `no-backend` | 跑在浏览器里（`npm run dev` 无后端） | 界面显示空态，不弹错误——用户看到的是「预览模式」 |
| `unknown` | 反序列化失败的兜底 | 显示原始 message，不猜 |

## 错误信息的形状

```jsonc
// invoke reject 时的载荷
{
  "code": "1001",
  "message": "文件读写失败",           // 给用户看的一句话
  "details": "The process cannot access the file..."   // 底层原因，进日志与排障面板
}
```

`normalizeError()` 处理三种情况：

1. reject 是 JSON 字符串 → 解析成 AppError；
2. reject 是对象 → 取 `code` / `message` / `details`；
3. 都不是 → `{ code: 'unknown', message: String(e) }`。

**不把 details 直接弹给用户**：`The system cannot find the path specified.
(os error 3)` 对用户没有意义。`translateIoDetail()` 把它翻成「路径不存在」。

## 取舍

| 选择 | 优势 | 代价 |
|---|---|---|
| 按域分段（1000/2000/3000…） | 前端按码段就能分流，不必逐个判等 | 新增时要先想清楚属于哪个域 |
| message 自带「下一步」 | 用户知道接下来干什么，而不是只知道失败了 | 写 message 的成本略高 |
| details 承载原始错误、不直接展示 | 排障有据可查，界面上又不会出现内部路径 | 前端要多一层翻译表（`utils/errors.ts`） |
| 两端不重复同一句话 | 后端给原因、前端给动作，改一处即可 | 需要后端与前端各读一份约定 |
